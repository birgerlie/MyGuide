# Tours — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A loop with a chosen duration, and A→B with at most 25 % detour, through the best places: planned,
previewed, walked with walking mode, and restored after relaunch.

**Architecture:**
- MyGuideCore: area place search, scoring, planning (insertion + 2-opt + budget), trimming against routed times,
  and an `ActiveTour` model with progress, all tested.
- App: MapKit walking routes (`MKDirections`), destination search (`MKLocalSearchCompleter`), the «Turer» tab,
  preview, tour panel on the Utforsk map, and walking-mode integration.
- Watch: the next stop on the guided walk screen.

**Spec:** `docs/superpowers/specs/2026-10-29-tours-design.md` (sections 4–8 binding).

**Branch:** `tours`, created from `around-me` after the refactor plan finishes.

## Global Constraints

- Everything in the around-me plan's Global Constraints: design tokens, coral filled CTAs with forest text,
  Playfair/Inter, Swift 6, no MyGuideCore in extensions, screen texts in the UI language (`UILanguage.current`),
  stories in the story language.
- Walking speed is 1.3 m/s, the detour factor 1.3 and the dwell 4 min per stop. The A→B budget is 1.25 × the
  direct walking time + dwell. The loop budget is the chosen duration. A routed total may exceed the budget by at
  most 10 %. At most 25 `MKDirections` requests per tour.
- Loop durations: 30, 45, 60, 90, 120 and 180 min. The loop radius is `min(2500, 1.3 × seconds / 2.5)` m.
- Candidates are tier top and good, plus wikiOnly only when fewer than 4 top/good exist. Scores are top 3, good 2,
  wikiOnly 1, and × 0.5 if heard in the last 30 days.
- Core: `cd Packages/MyGuideCore && swift test`.
- App: `xcodebuild -project MyGuide.xcodeproj -scheme MyGuide -destination 'generic/platform=iOS' -derivedDataPath /tmp/mg-dd -quiet build`.

## Review Focus

1. A loop that cannot fit even one stop: honest empty result, never a route through nothing. Pinned in T2.
2. Routing that times out or fails part-way: approximate straight-line legs, marked approximate, startable.
   Pinned in T3/T4.
3. A tour restored after relaunch whose stops were partly visited: «Neste» is the first unvisited stop. Pinned in
   T5.
4. A destination less than 200 m away: A→B degenerates to the direct route with no stops, and says so. Pinned in
   T2.
5. Two stops less than 60 m apart: arriving buzzes them one after the other, never both at once. Pinned in T5.

```swift
public enum TourArea: Sendable, Equatable {
    case loop(centre: Coordinate, radius: Double)
    case corridor(from: Coordinate, to: Coordinate, padding: Double)   // bbox of the line, padded by 30 % of its length
    public static func loop(from: Coordinate, minutes: Int) -> TourArea   // radius min(2500, 1.3 × s / 2.5)
```

### Task T2: Planner — insertion, 2-opt, budget (core)

**Files:** create `Tours/TourPlanner.swift` and `TourPlannerTests.swift`.

**Interfaces:**
```swift
public struct TourPlan: Sendable, Equatable, Codable {
    public enum Kind: String, Sendable, Codable { case loop, aToB }
    public var kind: Kind; public var start: Coordinate; public var end: Coordinate
    public var stops: [TourStop]        // ordered
    public var estimatedSeconds: Double // walking (straight × 1.3 / 1.3 m/s) + 240 s per stop
    public var budgetSeconds: Double
}
public struct TourStop: Sendable, Equatable, Codable, Identifiable { public var id: String; public var name: String; public var coordinate: Coordinate; public var tier: PlaceTier; public var score: Double }
public enum TourPlanner {
    public static let walkingSpeed = 1.3, detourFactor = 1.3, dwellSeconds = 240.0, overrunAllowance = 0.10
    public static func loop(from: Coordinate, minutes: Int, candidates: [TourCandidate]) -> TourPlan
    public static func aToB(from: Coordinate, to: Coordinate, candidates: [TourCandidate]) -> TourPlan
        // budget = 1.25 × direct estimate + 240 s per stop; direct < 200 m → no stops
    /// Drops the stop with the worst score ÷ saved seconds; the caller re-routes the two affected legs.
    public static func dropWorst(_ plan: TourPlan, legSeconds: [Double]) -> TourPlan
}
```
Insertion: repeatedly insert the candidate with the best score ÷ added seconds at its cheapest position while the
estimate stays ≤ budget. Then 2-opt over the stop order with fixed endpoints. Deterministic tie-break by id.

- [ ] Tests, hand-computed on a small grid of coordinates (use GeoMath distances, computed in comments):
  - the loop inserts the highest score ÷ time first;
  - the budget is respected;
  - 2-opt removes a crossing;
  - A→B with a 30 min direct route has budget 37.5 min + dwell;
  - a destination less than 200 m away gives no stops;
  - no candidate fits gives no stops;
  - dropWorst removes the right stop;
  - ties are broken deterministically.
- [ ] Commit `feat(tours): planner with insertion, 2-opt and budget`.

### Task T3: Routing and trimming (app + core glue)

**Files:** create `MyGuide/Tours/TourRouter.swift` (MKDirections walking, per leg, ≤ 25 requests, 10 s per
request) and `Packages/MyGuideCore/.../Tours/TourRouting.swift` (pure trim loop over leg results), with tests for
the core part.

**Interfaces:**
```swift
// core
public struct RoutedLeg: Sendable, Equatable, Codable { public var seconds: Double; public var metres: Double; public var path: [Coordinate]; public var approximate: Bool }
public struct RoutedTour: Sendable, Equatable, Codable { public var plan: TourPlan; public var legs: [RoutedLeg]; public var approximate: Bool
    public var totalSeconds: Double { get }   // legs + 240 s per stop
    public var totalMetres: Double { get } }
public enum TourRouting {
    /// Fits a plan: route legs via `leg`, drop the worst stop while total > budget × 1.10, re-route only the two
    /// affected legs; stop at 25 requests; a failed leg becomes an approximate straight leg (seconds from the estimate).
    public static func fit(_ plan: TourPlan, maxRequests: Int,
                           leg: @Sendable (Coordinate, Coordinate) async -> RoutedLeg?) async -> RoutedTour
}
```
- [ ] Core tests with a stub `leg`:
  - fits on the first try;
  - an over-budget result drops one stop and re-routes 2 legs;
  - the request cap stops further routing and leaves the rest approximate;
  - a failing leg becomes approximate and the tour is marked approximate.
- [ ] App: `TourRouter.leg(from:to:)` uses `MKDirections.Request` with `transportType = .walking`, returning
      `RoutedLeg` with the polyline coordinates and a 10 s timeout. Use the core `Deadline` from the refactor plan.
- [ ] Commit `feat(tours): walking routes and trimming to budget`.

```swift
public struct ActiveTour: Sendable, Equatable, Codable {
    public var routed: RoutedTour; public var startedAt: Date; public var visited: [String]; public var skipped: [String]
    public var next: TourStop? { get }                       // first stop neither visited nor skipped
    public var progress: (done: Int, total: Int) { get }
    public mutating func arrive(at position: Coordinate, now: Date) -> TourStop?  // within 60 m of `next` → marks visited, returns it; never two at once
    public mutating func skipNext()
    public var isFinished: Bool { get }                      // all stops done and within 60 m of `end`, or ended
}
```
